# 06 — 출력 검수

`qa/seconds/sec-00.png` … `sec-29.png`: 제작본을 0~29초 정수 위치로 렌더한 1080 PNG 30장. 원본 사진과 짝을 지어 비교 페이지에 표시한다.

브라우저 캡처 재생성: 로컬 플레이어를 연 뒤 `window.app.captureSeconds()`를 호출한다. `server.mjs`가 로컬 same-origin POST PNG만 정해진 qa 폴더에 저장한다. 외부 업로드는 없다.

검수 항목: 30초 전 구간 렌더, 액체가 잔 바깥으로 나오지 않는지, 병 입구와 줄기가 연결되는지, 얼음 투입과 따르기/젓기/껍질 순서, 원본 시간 동기화, 모든 생성 원화·30쌍 사진 로딩, 모바일 레이아웃, 콘솔 오류.

생성 원화의 세부 형태와 서체, 카드의 전환 타이밍에는 차이가 남는다. 사진 기준 재현 시안이며 사용자 승인된 완성본으로 기록하지 않는다. V1에는 MP4가 없었으며, V2에서 아래 영상 파일을 추가했다.

실제 결과: `qa/report.json`. 원본/제작본 1080 PNG 각 30장, 갤러리 60장 로딩 실패 0, 재생 확인 시각 13.280488초에서 양쪽 시간 차이 0초, +1F 이동 1/30초, 모바일 390px 가로 넘침 없음. `desktop-final.png`는 28초 비교 화면이다.

V2: `qa/deciseconds/`에 0.1초 JPEG 300장, `render/`에 30초 전체·6초 앞부분·6초 좌우 비교 MP4를 저장했다. 모든 영상은 무음이다. 렌더는 브라우저의 WebCodecs H.264 → ffmpeg MP4 재포장 방식으로 실제 Three.js 장면 900프레임을 굽는다.

V2 실제 결과는 `qa/report-v2.json`: 원본/제작본 0.1초 사진 각 300장, 30초 900프레임, 6초 180프레임을 확인했다. 0.1초 이동·구간 반복·현재 사진 로딩·모바일 가로 넘침을 검수했다. 제목·얼음 관찰표는 `qa/title-01s-comparison.jpg`, `qa/ice-01s-comparison.jpg`.

V3 (2026-10-29): 얼음을 원본 30fps 추적값으로 재제작. `render/tree002-v3-30s.mp4`, `tree002-v3-intro-6s.mp4`, `tree002-v3-compare-intro-6s.mp4`, `tree002-v3-compare-ice-slow.mp4`(3.9~5.9초 0.5배속 좌우). `qa/deciseconds/`는 V3로 갱신했고 V2 사진·소스·MP4는 `baseline-v2/`. 검증: 같은 추적기로 V3를 다시 재서 원본 대비 위치 오차 중앙값 0.4px·90% 0.7px·최대 6.3px, 각도 0.4°.
