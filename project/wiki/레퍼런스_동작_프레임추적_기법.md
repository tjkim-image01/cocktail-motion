# 레퍼런스 동작을 똑같이 만드는 기법 — 프레임 추적

기록일: 2026-10-29. 출처 작업: [tree002 Negroni V3 얼음](../sample/03_모션제작/얼음_V3_프레임추적.md), [V4 30초 전체 + 효과음](../sample/03_모션제작/V4_전체_프레임측정.md).
대상: 참고 영상의 물체 동작(낙하·반동·회전·효과선)을 Three.js/Canvas로 **최대한 같게** 다시 만들 때.

## 핵심 결론

> 눈으로 키를 찍지 말고, **원본의 모든 프레임에서 물체의 위치·각도·크기를 재서 그 값을 그대로 키로 쓴다.** 그리고 만든 영상을 **같은 측정기**로 다시 재서 숫자로 비교한다.

tree002에서 같은 얼음 3개를 세 번 만들었다.

| 버전 | 키를 얻은 방법 | 결과 |
| --- | --- | --- |
| V1 | 1초 간격 사진을 보고 키 | 원본과 크게 다름 |
| V2 | 0.1초 간격 사진 + 사이를 곡선으로 추정 | 위치 오차 최대 46px, 각도 7°, 효과선·충돌 높이 추측이 틀림 |
| V3 | **30fps 전 프레임 자동 추적** | 위치 오차 중앙값 0.4px, 각도 0.4° |
| V4 | 같은 방법을 30초 전체(UI·컵·액체·병·줄기·스푼·껍질·선 떨림)로 확장 | 화면 평균 차이 6.01 → 3.40, 잔 영역 14.1 → 4.9 |

0.1초(3프레임)도 빠른 동작에는 너무 성기다. 낙하 물체는 프레임당 90px 넘게 움직이고 충돌·반동은 1~2프레임 안에 일어난다. 사진 사이를 '그럴듯하게' 이으면 충돌 높이·회전·효과선 규칙을 추측하게 되고, 그 추측이 '이상한 부분'이 된다.

## 절차

### 1. 무엇이 움직이는지 먼저 본다 (1프레임 비교표)

원본과 현재 제작본을 같은 프레임끼리 좌우로 붙인 시트를 만든다. 확대 크롭으로 **그림 자체**도 비교한다. 동작보다 그림 차이가 더 이상하게 보이는 경우가 많다(tree002: 파란 3D 큐브 vs 먹선 둥근 사각형).

- 프레임 추출: `ffmpeg -i in.mp4 -t 7 dir/o-%03d.png` (파일 번호 = 프레임+1)
- 같은 크롭·같은 축소율로 원본|제작본 쌍을 격자로 배치

### 2. 측정용 '새 먹선' 지도

- 물체가 나오기 직전 프레임을 **배경 기준 프레임**으로 둔다.
- 각 프레임의 어두운 화소(회색 180 미만)에서 기준 프레임의 어두운 화소(3×3 팽창)를 빼면 새로 생긴 선만 남는다.
- 물체의 **안쪽 표식선**(하이라이트 등)까지 포함되도록 임계값을 정한다. 정사각형 윤곽만 쓰면 90° 회전이 구분되지 않는다.
- 물체가 화면 위에서 들어오면 위쪽에 여백(패딩)을 붙여 반쯤 보이는 프레임도 매칭한다.

### 3. 회전 템플릿 추적

- 다른 것과 겹치지 않은 프레임에서 물체 하나를 잘라 템플릿으로 쓴다. 최소 사각형(minAreaRect)으로 템플릿의 기준 각도를 구한다.
- 각 프레임에서 `각도(±20°, 2° 간격) × 위치`를 정규화 상관(TM_CCORR_NORMED)으로 찾고, 찾은 근처에서 `각도 ±2°(1° 간격) × 배율 0.94~1.06`으로 다시 다듬는다. 점수 꼭짓점에 포물선 보간을 해 소수 픽셀까지 얻는다.
- **예측 + 속도 비례 창**: 다음 위치 = 현재 + 직전 속도. 반동은 속도를 뒤집으므로 세로 창 = 30 + 1.6×|속도|. 가로 창은 좁게(±14px) 두어 옆 물체로 건너뛰지 않게 한다.
- 시드는 물체가 **공중에 혼자 있는** 프레임에 둔다. 다른 선(잔 입구 등)과 겹친 프레임을 시드로 쓰면 이웃 물체로 건너뛴다. 시드에서 앞뒤 양방향으로 추적한다.
- 시드에는 대략의 초기 속도를 준다(정지로 시작하면 첫 프레임의 큰 이동을 놓친다).

코드: [`project/sample/scripts/track_ice.py`](../sample/scripts/track_ice.py). 실행 `uv run --with opencv-python-headless --with numpy python scripts/track_ice.py VIDEO OUT.json`. 새 작품에서는 `BASE`, `TEMPLATE_FRAME`, `SEEDS`, 관심 영역(가로 170~530, 세로 <820)만 바꾼다.

### 4. 추적 결과 확인

- 원본 위에 추적한 사각형과 방향 표시를 겹쳐 그린 시트를 눈으로 본다. 점수가 낮은 프레임(다른 선을 가리는 순간)만 따로 확인한다.
- 정리는 최소로 한다: 이상치 x만 중앙값으로, 안착 뒤 1px 흔들림만 고정. **나머지는 측정값 그대로** 쓴다. [`make_ice_v3.py`](../sample/scripts/make_ice_v3.py)

### 5. 효과선도 측정해서 재생한다

- 물체 윤곽을 지운 나머지 짧은 먹선 덩어리를 선분(주성분 방향의 양 끝점)으로 바꾼다.
- 물체 중심과의 거리·방향으로 진짜 효과선만 고른다. 프레임별로 '어느 물체 기준 상대좌표'로 저장하면 물체를 따라 움직이는 선을 그대로 재생할 수 있다.
- tree002에서 밝혀진 규칙: 첫 충돌 때만, 충돌 1프레임 전부터 5~6프레임, 얼음 중심에서 48~68px 위쪽에 회전하지 않는 선 3개. 두 번째 반동에는 없음. 이런 규칙은 추측으로는 맞히기 어렵다.

### 6. 재생: 프레임 값 그대로

- 플레이어는 `t×30` 프레임 앞뒤 두 측정값을 **선형 보간**만 한다. 원본에 없던 스쿼시·스트레치·이동선은 넣지 않는다.
- 효과선 같은 손그림 요소는 원본처럼 프레임 단위로 바뀌게(`floor(t×30)`) 둔다.
- 등장 프레임도 측정한다(tree002: 페이드 없이 4.000/4.367/4.700초에 반쯤 보이는 상태로 등장).
- UI 변화(카운터 등)도 같은 방식으로 재면 물체 사건과 맞는지 확인할 수 있다(tree002: 카운터 = 안착 프레임 143/153/164).
- 그리기 순서도 원본에서 확인한다(떨어지는 얼음이 제목·잔 입구 앞).

### 7. 그림을 원본 치수로

- 물체를 측정 각도만큼 되돌려 축 정렬한 확대 크롭에서 크기·선 굵기·모서리 반경·채움색·안쪽 선 위치를 잰다.
- 단순한 아이콘은 그 치수로 벡터(Canvas Path2D → CanvasTexture)를 그리는 편이 생성 이미지보다 원본에 가깝다. 약간의 고정 흔들림으로 손그림 느낌을 낸다.
- 원본 영상의 화소를 잘라 제작본에 쓰지 않는다. 원본은 비교용이다.

### 8. 같은 측정기로 검증

- 제작본 MP4를 같은 추적기로 재고 원본 추적값과 프레임별로 뺀다: 위치 오차 중앙값·90%·최대, 각도 오차.
- 모든 각도에서 같은 방향으로 치우친 오차는 그림 중심의 문제다. 메시 위치 보정값으로만 고치고 동작 데이터는 건드리지 않는다(tree002: 0.8px, 1.9px → 오차 중앙값 2.1 → 0.4px).
- 마지막으로 원본/제작본 좌우 0.5배속 영상을 만들어 사람 눈으로 본다. 숫자 통과만으로 끝났다고 판단하지 않는다.

## V4에서 추가된 기법 (30초 전체로 넓힐 때)

### A. 먼저 시간표를 수치로 뽑는다
영역(병·잔·카드·타임라인…)마다 이웃 프레임 차이를 재고, 움직이는 구간을 프레임 번호로 나열한다. 1초 사진으로 짐작한 전환은 자주 틀린다.
tree002의 예: 카드가 "한참 사라졌다 나타난다"고 봤지만, 실제로는 **1프레임만** 큰 글자가 혼자 나왔다.

### B. 독립 영역은 병렬 측정 에이전트에게 맡긴다
- UI / 술병·줄기 / 잔 안쪽처럼 서로 안 겹치는 영역으로 나눈다.
- 각 에이전트 지시서에 넣을 것:
  - 영상 경로, 프레임·좌표·각도 규칙(0-based, y 아래, 시계방향 +)
  - 이미 아는 사실(선 떨림 등)
  - 출력 위치·형식: `data.json`(schema 포함), `README.md`, 검증 오버레이
  - "측정만 하고 플레이어는 건드리지 않기"
- 네트워크 오류로 멈추면 같은 에이전트에 이어서 하라고 보내면, 중간 결과부터 계속한다.
- 결과는 `scripts/v4/make_*_v4.py`로 플레이어용 JSON으로 압축한다. 값이 바뀌는 프레임만 남기는 run 형식을 쓴다. README에 적힌 사건 프레임으로 잡음 검출을 걸러낸다.

### C. 선 떨림(line boil)도 측정해서 넣는다
- 정지한 글자·선 영역에서 이웃 프레임 잉크 차이가 튀는 프레임을 찾는다. 그 주기를 `floor(t×8)` 같은 식에 맞춘다. tree002는 8Hz, 190/190 일치.
- 떨림 크기와 결은 광학 흐름으로 잰다: 변위 표준편차, 4·8·16px 거리의 상관.
- 재현은 화면 전체 후처리로 한다: 값 노이즈 UV 왜곡, 상태마다 시드 변경. 제작본을 같은 스크립트로 다시 재서 크기·셀 크기를 맞춘다(`boil_field.py`).

### D. 선이 그려지며 등장하는 물체
- 측정 도형(옆선·입구 타원·바닥 곡선…)을 선마다 점열로 만든다.
- 각 프레임에서 점마다 근처에 잉크가 있는지 본다 → 그려진 비율, 어느 끝부터 그려지는지 얻는다.
- 재생할 때는 같은 점열을 그 비율만큼 그린다. 채움색 투명도는 몸통 픽셀 색의 변화로 얻는다.

### E. 주변 색을 받는 물체 (액체 속 얼음·스푼)
- 같은 위치의 물체 색과 주변 액체색을 여러 시점에서 뽑는다. `물체 = mix(원래색, 액체색, a)`의 a를 구한다(tree002: 0.62, 젓는 동안 0.83).
- 외곽선은 따로 잰다.
- 재생할 때는 물체를 한 번 그리고, **수면 아래 영역으로 잘라** 물든 색으로 다시 그린다. 수면 타원의 뒤쪽 선 아래까지가 수면 아래다.

### F. 렌더 색 함정 — BT.709 vs BT.601
- 브라우저 WebCodecs H.264는 BT.709로 표시된다. 원본이 BT.601이면 진한 색이 어둡게 측정·표시된다.
- 확인 방법: 플레이어 캔버스 픽셀(정답)과 영상 디코딩 픽셀을 비교한다.
- 해결: `ffmpeg -vf "colorspace=all=bt601-6-625:iall=bt709:fast=1"` 후 BT.601 태그를 붙인다.

### G. 전체 화면 차이로 회귀 확인
- 5px 흐림 후 평균 RGB 차이를 영역별·초별로 낸다(`compare_frames.py`). 이전 버전과 같은 표로 비교한다.
- 가장 나쁜 프레임만 원본 해상도로 크롭해 눈으로 원인을 찾는다. tree002에서 이렇게 찾은 것: 껍질 굵기, 수면 띠의 물듦, 액체 바닥 모양.
- 같은 서체가 아니거나 선 떨림 위상이 다르면 차이가 2~4 남는다. 이것을 바닥값으로 본다.

### H. 효과음은 측정된 사건에서 배치한다
- 사건 프레임에서 큐를 자동으로 만든다: 충돌(추적 속도가 뒤집히는 프레임), 등장·전환 프레임, 따르기 시작~끝, 숟가락 방향 전환 등.
- 큐마다 근거를 `note`로 남긴다. 소리는 코드로 합성한다(`scripts/v4/sfx.py`).
- 배경음악은 프로젝트 음악 검수 규칙(후보 청취 → 사용자 선택)을 따로 따른다.

## 한계

- 템플릿 매칭은 모양이 바뀌지 않는 단단한 물체(얼음, 아이콘, 글자)에 맞다. 액체·연기·몸처럼 모양이 변하는 것은 따로 다뤄야 한다.
- 다른 물체 뒤에 크게 가려지는 프레임에서는 점수가 떨어진다. 그 프레임만 눈으로 확인하고 정리한다.
- 원본 영상을 측정 자료로 쓰는 것은 로컬 연구 범위다. 공개 배포는 별도로 판단한다.
