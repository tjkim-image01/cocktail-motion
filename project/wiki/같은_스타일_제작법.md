# 같은 스타일의 레시피 모션그래픽 만들기

기준은 [Negroni sample](../sample/README.md)의 V4다. 단순히 물건을 배치하는 데서 끝내지 않고, 글자·선·액체·카드·효과음까지 하나의 시간표로 연결한다. 실제 파일 위치는 [코드 지도](샘플_코드_지도.md), 시작 절차는 [새 작품 시작](새_작품_시작.md)을 따른다.

## 1. 화면과 그림

- 1080×1080 정사각형, 크림색 바탕 `#faf9f5`, 짙은 먹선, 산호색 제목과 포인트. 물건은 왼쪽, 설명 카드는 오른쪽, 진행 단계는 아래쪽에 둔다.
- 원본 확대 사진에서 물건의 폭·높이·선 굵기·모서리·색칠 어긋남을 먼저 정한다. 병의 색칠은 먹선보다 약 2~3px 왼쪽으로 어긋난다. 새 소재의 수치는 새로 정한다.
- 굵은 제목과 손글씨 설명을 구분한다. 샘플은 로컬에 보관한 Luckiest Guy·Patrick Hand 등을 사용하며 원본과 완전히 같은 서체는 아니다. 서체 파일과 라이선스를 함께 보존한다.
- 화면 전체 선 떨림은 `boil.js` 후처리다. 샘플은 `floor(t×8)`로 상태를 바꾸고 약 1.2px 크기의 변위를 준다. 물건별 위치 흔들림으로 대체하면 서로 다른 느낌이 된다.

초기 V1·V2는 물건별 Imagegen 투명 PNG를 만들었다. `02_아이콘제작/assets`, `prompts`, `manifest.json`에 결과를 보존했다. **V4 실제 화면의 물건은 측정 치수로 그린 Canvas 벡터**다. 그림 한 장을 Three.js 평면에 올리고 선 떨림을 적용한다. 물건을 독립 3D 메시로 만든 구조는 아니다.

새 물건의 원화가 필요하면 imagegen으로 개별 제작하고 프롬프트·출처를 함께 저장한다. 원본에 가까운 단순 먹선 도형은 V4처럼 벡터로 제작하는 방법도 쓸 수 있다. 선택한 방법은 해당 작품 README에 적는다.

## 2. 시간과 동작

먼저 0.1초 간격 사진으로 사건을 정리한다. 낙하·충돌·짧은 전환은 원본 FPS의 모든 프레임에서 확인한다. 이 샘플은 30fps, 30초, 총 900프레임이다. 프레임은 0부터, 원점은 좌상단, y는 아래 방향, 양의 회전은 시계방향이다.

| 대상 | 샘플의 움직임 | 새 작품에서 바꿀 것 |
| --- | --- | --- |
| 제목 | 글자별 지연 등장·팝, 이후 위로 이동 | 문자열과 글자별 등장·위치·폭·회전 배열 |
| 컵 | 선을 순서대로 그린 뒤 채움·빛 반사 등장 | 선 점열, 그리기 방향·비율·시각 |
| 얼음 | 화면 위에서 낙하, 충돌·반동·안착 | 프레임별 x·y·각도, 등장·효과선 프레임 |
| 카드 | 큰 글자가 먼저, 한 프레임 뒤 카드, 약 12.5프레임 동안 easeOutBack | 단계 수, 문구, 사건 프레임 |
| 병 | 진입→기울임→따르기→세움→퇴장 | 병 모양·크기·궤적·색·시각 |
| 줄기 | 병 입구에서 자라 수면 도달, 끝에는 꼬리가 낙하 | 중심선·폭·낙하 끝점 |
| 젓기 | 스푼 큰 좌우 왕복과 얼음의 엇갈린 원운동 | 주기·진폭·시작·종료 |
| 마무리 | 껍질 비틀기·향 방울, 빛살, 약한 컵 확대 | 새 장식과 마무리 사건 |

빠른 동작을 몇 개의 키와 임의 bounce 함수만으로 복원하지 않는다. 추적값을 앞뒤 두 프레임 사이에서 보간하고, 효과선은 프레임 단위로 교체한다. 세부 측정법은 [프레임 추적 문서](레퍼런스_동작_프레임추적_기법.md)에 있다.

## 3. 물은 직접 그린다

물이 자동으로 생기는 구조가 아니다. `world.js`가 수위·색·수면 타원·밝은 수면 띠·바닥 경계선을 그리고 잔 내부로 잘라낸다. `bottles.js`는 따르는 줄기와 물방울을 그린다. 수위 데이터와 줄기 끝점을 같은 시간으로 맞춰야 한다.

잠긴 얼음은 수면 아래 부분을 다시 칠한다. 샘플에서는 얼음과 액체색의 혼합 비율이 0.62, 젓는 동안 0.83이다. 외곽선의 물듦과 흰 반사도 함께 그린다. 액체마다 기포의 색·형태가 다르다. 새 음료에서 이 값을 그대로 쓰기보다 그 음료의 투명도와 색을 보고 조정한다.

## 4. 가림과 선 떨림

샘플의 큰 순서: 제목 → 잔 뒤쪽 → 액체 → 얼음 → 잔 선 → 스푼 → 장식·빛살 → 충돌선 → 병·줄기 → 눈금 → 카드 → 타임라인. 실제 세부 순서는 `world.js`, 전체 순서는 `scene.js`에 있다. 레이어 순서가 바뀌면 얼음이 컵 밖에 있거나 줄기가 앞뒤를 잘못 통과하는 인상이 난다.

선 떨림에는 재생 시간 `t`를 넣어 같은 시각의 그림이 항상 같게 한다. `performance.now()`만으로 떨림을 만들면 정지 비교와 영상 출력 결과가 달라진다.

## 5. 효과음과 검수

효과음 큐는 등장·충돌·따르기·젓기·완성의 사건 프레임에서 만든다. `make_sfx_events.py`가 큐와 근거를 JSON으로 만들고 `sfx.py`가 합성한다. 현재 WAV는 30초이며 앱의 애니메이션·원본과 같은 시계로 탐색·일시정지·배속을 적용한다. 배경음악은 없다.

비교 페이지에서 같은 프레임을 정지하고, 빠른 구간은 0.5배속과 구간 반복으로 본다. 그림 형태·충돌·가림·수면·문구 전환을 함께 확인한다. 전체 평균 화소 차이만으로 완료 판정을 내리지 않는다. 효과음은 실제로 들어 크기·질감·타이밍을 확인한다. 기존 V4 기록은 합성음의 레벨만 확인했다고 명시하므로 청취 검수 완료로 간주하지 않는다.

최종 H.264 출력 후 캔버스와 영상의 빨강을 비교한다. 샘플의 WebCodecs 출력은 BT.709, 원본은 BT.601이라 색 변환이 필요했다. 모든 새 영상에 같은 변환을 무조건 적용하지 말고 실제 태그와 디코딩 색을 확인한다. [V4 기록](../sample/03_모션제작/V4_전체_프레임측정.md)에 기존 출력·측정 결과가 있다.
