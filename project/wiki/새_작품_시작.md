# 새 작품 시작

작업 루트는 `/Users/jatu/app/cocktail`이다. `sample`을 보존하고 새 작품을 `project/c001`, `c002`처럼 만든다. 현재 코드에는 Negroni 전용 치수·문구·시간이 있으므로 소재를 입력하면 자동 완성되는 템플릿은 아니다.

## 복사와 실행

```sh
cd /Users/jatu/app/cocktail
# c001이 아직 없는 상태에서 실행한다.
cp -R project/sample project/c001
cd project/c001
PORT=4344 npm start
```

샘플은 4343, 새 작품은 다른 포트를 쓴다. 서버의 `PORT` 환경변수는 영상 내보내기·캡처 요청의 origin 검사에도 적용된다. 새 작품의 기본 포트를 고정하려면 `server.mjs`의 기본값, README URL, `플레이어 실행.command`를 함께 바꾼다. 루트의 `npm start`는 계속 기준 샘플을 실행한다.

## 반드시 찾아서 바꿀 연결

- `intro-motion-v3.json`: 제목 문자열과 글자별 시간·중심·폭·각도 배열을 같은 글자 수로 맞춘다. `intro.js`의 제목 그리기도 확인한다.
- `ui-v4.json`, `ui.js`: 카드 문구·단계 수·하단 타임라인 문구. `app.js`의 `cues`, 반복 구간도 같은 시간표로 바꾼다.
- `world.js`, `bottles.js`: 새 잔·병·장식 그림. `glass-v4.json`, `bottles-v4.json`: 위치·수위·색·회전·사건.
- `compare.html`의 원본 영상, `app.js`의 효과음·아이콘·사진 경로와 `fillFilmstrip()` 범위.
- 길이를 바꾸면 `scene.js`의 시간 제한, `app.js`의 30초·30fps·900프레임·300장, HTML의 슬라이더/시간 표시, 효과음 길이도 바꾼다.
- `tree002` 파일명은 플레이어 다운로드, 서버 저장 경로, 합성·분석 스크립트에도 있다. 새 작품 식별자로 통일한다.
- 분석 스크립트의 관심 영역·시드·측정 프레임·색 임계값은 새 원본에 맞춘다. 기존 JSON만 재생성한다고 새 원본이 자동 추적되지는 않는다.

실행 의존성은 샘플 안의 Three.js·서체·영상·JSON이다. 공용 `lib`는 루트에 복사했으며 현재 플레이어는 그것 없이도 실행된다. `lib`의 외부 서비스 연결 코드는 해당 서비스 설정이 필요할 수 있다.

## 분석 환경

```sh
cd /Users/jatu/app/cocktail/project/c001
../../.venv/bin/python scripts/v4/make_ui_v4.py
../../.venv/bin/python scripts/v4/make_glass_v4.py
../../.venv/bin/python scripts/v4/make_bottles_v4.py
```

위 명령은 **이미 측정한 analysis-v4 자료를 플레이어 JSON으로 만드는 단계**다. 먼저 새 원본 측정이 필요하다. Python 환경을 새로 만들 때는 루트의 `requirements-analysis.txt`를 사용한다. 영상 추출·합성에는 별도 FFmpeg가 필요하다. 원본을 그대로 재생하는 동영상 플레이어로 제작본을 대체하지 않는다.

## 출력 전 확인

원본/제작본 동시 탐색 → 글자·낙하·충돌·수면·젓기 슬로 비교 → 효과음 청취 → 새 0.1초 사진 → MP4와 색 확인 순서로 검수한다. `window.app.captureTenths()`는 캡처를, `window.app.exportVideo()`는 H.264를 해당 작품 서버에 저장한다. H.264만 내보내므로 최종 MP4의 효과음 합성과 색 확인을 별도로 수행한다.
