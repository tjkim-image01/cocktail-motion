- 실제 결과: `project/m007/head_turn_v8/` (플레이어 http://127.0.0.1:4337/head_turn_v8/index.html)
- 실험 비교·실패 원인 분석: `wiki/2D애니메이션/m007_고개회전_분석.md`

```

  web/headturn.js       Three.js 런타임: 부위 메시 + 깊이장 변형 + 연기(숙임·깜빡임·머리카락 지연)
```

## 1 핵심 원리

**3D 모델을 만들지 않는다. 그림 전체를 보간(모핑)하지도 않는다.** 정면 원화를 부위 레이어로 나누고, 각도 하나로 모든 부위를 *서로 다른 양만큼* 움직인다.

- 레이어마다 5px 격자 평면 메시. 정점 이동은 `x' = x + sin(각도) × 깊이(x, y)`.
- 깊이장 = 돔(단면 `cos(π/2·r)`) + 가우스 돌출(코·입·턱·앞머리) + 세로 경사(목).
  - 코는 많이, 눈은 중간, 윤곽은 적게 움직인다. 돔의 기울기 때문에 먼 쪽 눈은 좁아지고 가까운 쪽 볼은 넓어진다.
  - **얼굴과 머리카락은 다른 깊이장**을 쓴다. 이 차이가 시차(앞머리가 이마 위를 미끄러짐)를 만든다.
  - **앞머리 레이어와 뒷머리 레이어는 같은 깊이장**을 쓴다. 그래야 둘 사이의 자른 경계가 움직여도 보이지 않는다.
- 레이어 안쪽은 흰색으로 채워서 위 레이어가 아래를 가린다(선화 + 흰 면).
- 먼 쪽으로 넘어가는 부위(묶음 머리)는 음의 깊이로 반대 방향으로 움직이고, 각도에 따라 커지는 머리 외곽 타원으로 잘라 머리 뒤로 숨긴다(`clip`).
- 깜빡임: 속눈썹 띠는 굵기를 유지한 채 내려오고, 그 아래 눈동자만 아래 눈꺼풀 쪽으로 접힌다(`blink.lash`, `blink.y`).
- 연기: 1초 회전(smootherstep 가속·감속), 회전 중 3.5° 숙였다 들기, 1.5° 갸웃, 회전 초반 깜빡임, 머리카락 끝은 용수철(`hairSpring`)로 늦게 따라온다.

레이어(그리기 순서): `hair_back`(턱 아래 뒷머리) → `neck` → `face`(피부·윤곽·눈썹·코·입) → `eye_l` → `eye_r` → `hair_front`(앞머리·옆머리·귀·머리핀) → `bun`(선택).

## 2 새 캐릭터에 적용하는 순서

저장소 루트에서:

```sh
PY=/Users/jatu/.venvs/bongsik-morph/bin/python
OUT=project/m0xx/head_turn
```

1. **원화 준비** — 정면, 흰 배경, 깨끗한 선화 한 장(V8은 724×724). 좌우 원화가 있으면 같은 생성 시트(같은 크기·선 굵기)에서 나온 것만 보충 재료로 쓴다. **묶음·머리핀 같은 비대칭 요소가 좌우 그림에서 같은 쪽에 있는지 먼저 확인한다**(V4는 셀 9→10에서 묶음이 반대쪽으로 바뀌어 모든 보간이 실패했다).
2. **플레이어 복사** — `$PY -m lib.com.jatu.anim.anim_object init $OUT` (index.html, app.js, headturn.js, style.css, vendor/, rig.json 예시. 있는 파일은 덮어쓰지 않는다)
3. **영역 번호 지도** — `$PY -m lib.com.jatu.anim.anim_object labels front.png -o $OUT/qa/labels.png`
   얼굴 피부·눈썹 사이·눈 안쪽·이마 V자처럼 **얼굴에 속하는 닫힌 영역 안의 점**을 골라 spec의 `skin_seeds`에 적는다.
4. **spec 작성** — `examples/sera_m007.json`을 복사해 좌표를 그 원화에 맞게 바꾼다(아래 3절).
5. **자르기** — `$PY -m lib.com.jatu.anim.anim_object cut spec.json -o $OUT`
   `qa/layer_map.png`(부위 색 지도)와 `qa/front_diff.png`(정면 합성과 원화의 차이)를 본다. 평균 차이는 2.6/255 안팎이어야 한다(2배 확대·축소 오차).
6. **깊이장 조정** — `$OUT/rig.json`의 `fields`(돔 중심·반지름·깊이, 돌출 위치)를 새 얼굴에 맞춘다. `$PY -m lib.com.jatu.anim.anim_object preview $OUT --angles=-30,0,30`으로 빠르게 확인하고, 출력되는 **접힘 검사 값이 1 미만**인지 본다(1 이상이면 메시가 접힌다).
7. **가려진 뒷머리 보충** — 좌우 옆모습이 있으면 spec의 `fill`을 채우고 `$PY -m lib.com.jatu.anim.anim_object fill spec.json -o $OUT`. **반드시 cut 다음에** 실행한다(cut이 hair_back.png를 새로 만든다).
8. **브라우저 확인** — http 서버로 `$OUT/index.html`을 연다(file://는 안 된다). 부위 색 보기·변형 메시 보기·입체감·0.25배속으로 확인한다.

## 3 spec 항목 (원화 픽셀 좌표)

| 키 | 뜻 |
| --- | --- |
| `image` | 정면 원화 (spec 파일 위치 기준 경로) |
| `scale` | 텍스처 배율(2 권장) |
| `skin_seeds` | 얼굴 쪽 닫힌 영역을 고르는 점들 (`labels` 지도에서) |
| `front_y` | 이 높이 위의 머리카락은 얼굴 앞(`hair_front`), 아래는 뒤(`hair_back`). 턱선이 머리카락 앞에 오기 시작하는 높이 |
| `front_extra` | `front_y` 아래지만 얼굴 앞에 있는 다발(예: 볼을 덮는 옆머리 `lock`)의 다각형 이름 |
| `head` | 머리 외곽 타원. 묶음을 가리는 경계와 덮인 외곽선 보충에 쓴다 |
| `poly.forehead` | 앞머리 밑으로 이어지는 이마. 얼굴 레이어가 여기를 흰색으로 채운다(앞머리가 움직이면 드러남) |
| `poly.eye_l / eye_r` | 깜빡임용 눈 영역. 속눈썹 끝까지 포함하고 눈썹·머리카락은 피한다 |
| `poly.neck` | 목·어깨 |
| `poly.bun / tie` | (선택) 묶음 머리와 고리 |
| `chin_line_y` | 이 아래의 굵은 턱 끝 선은 끝까지 얼굴이 갖는다 |
| `bun_cap` | 묶음 밑을 지나는 머리 외곽선을 그려 넣을 타원 각도 범위 |
| `neck_ext` | 턱 밑으로 이어지는 목선을 그려 넣을 위치(얼굴이 밀리면 보인다) |
| `fill.sources[]` | 옆모습 원화: `side`(드러나는 쪽), `sign`(+1 = 화면 오른쪽을 보는 각도), `image`, `crop`, `chin`(턱 끝 y), `edge`(가까운 쪽 얼굴 경계 폴리라인) |

rig.json의 `layers.*`: `field`(face/hair/neck), `lag`(머리카락 지연 범위·양), `blink`(`lash` 속눈썹 띠 아래 끝, `y` 아래 눈꺼풀), `tuck`(묶음의 음의 깊이), `clip`(1 = +각도에서 숨김, -1 = −각도). `view`(화면에 보일 범위), `pivot`(갸웃 회전 중심).

## 4 선 소유 규칙 — 이것이 틀리면 유령선·끊김이 생긴다

V8 제작 중 실제로 겪은 결함과 해결이다. `cut`에 모두 반영되어 있다.

1. **선 한 줄은 한 레이어가 갖는다.** 두 레이어가 반씩 나눠 가지면 서로 다르게 움직일 때 선이 점선처럼 갈라진다.
2. **앞머리 밑(이마) 쪽 경계선은 얼굴이 복사해 갖지 않는다.** 얼굴 채움이 앞머리 밑으로 이어지므로 복사본이 앞머리가 미끄러질 때 이마 위 점선으로 드러난다.
3. **얼굴 안의 작은 틈 조각(눈썹 이중선 사이 등)은 머리카락이 아니다.** 300px 미만 조각을 머리카락에서 빼지 않으면 흰 조각이 눈썹 위를 미끄러지며 가린다. 채움과 소유 둘 다에서 빼야 한다(소유에서만 빼면 정면에서 선이 사라진다).
4. **눈 영역을 머리카락 채움에서 통째로 빼지 않는다.** 눈이 움직이면 그 자리가 구멍으로 보인다. 눈꼬리 선 자리만 1px 비운다.
5. **굵은 턱 끝 선은 아래 가장자리까지 얼굴이 갖는다.** 일부가 목 레이어에 남으면 ±30°에서 두 번째 턱선이 생긴다.
6. **목·묶음 밑처럼 원화에서 가려진 선은 그려 넣는다**(`neck_ext`, `bun_cap`). Live2D 작업에서 가려진 부분을 미리 그려 두는 것과 같다.

## 5 가려진 뒷머리 보충(fill)

얼굴이 옆으로 밀리면 턱선 양옆에 폭 10~15px(30°)의 띠가 드러난다. 원화에는 그 자리가 없으므로 옆모습 원화에서 가져온다.

- +각도(화면 오른쪽을 봄) → 왼쪽 띠 → **오른쪽을 보는** 옆모습에서. −각도 → 오른쪽 띠 → 왼쪽을 보는 옆모습에서.
- 대응: 같은 높이의 줄에서 **“얼굴 경계 바깥으로 k픽셀”** 위치끼리 맞춘다. 옆모습이 우리 각도보다 더 돌아가 있어도 턱선 바로 바깥의 머리카락을 가져온다. 그림 전체를 정합(affine·광학 흐름)하면 옆모습의 얼굴이나 턱선이 머리카락 자리로 들어오므로 쓰지 않았다.
- 옆모습 원화는 가까운 쪽 볼 윤곽선이 없고 머리카락 다발이 경계인 경우가 많다. 자동 영역 찾기는 선의 틈으로 새어 나가므로 `edge` 폴리라인을 직접 지정한다. `qa/fill_hidden_source_*.png`에서 초록 선(경계)과 빨간 점(가져온 위치)을 확인한다.
- 붙인 그림은 `hair_back`(얼굴보다 아래)에만 들어가므로 정면에서는 보이지 않는다. 범위는 입체감 160%까지(`s_fill` 0.8) 계산한다.
- 디자인이 어긋난 옆모습이라도 이렇게 **가려진 부분의 국소 재료**로는 쓸 수 있다.

## 6 검수

- 정면 합성 차이(`qa/front_diff.png`)가 선 모양을 따라 진하게 보이면 소유·채움이 틀린 것이다. 연하게 전체에 퍼진 것은 확대·축소 오차다.
- ±15°, ±30°를 **부위 색 보기로 확대**해서 점선·흰 구멍·유령선을 찾는다. 수치 통과만으로 끝내지 않는다. 판단은 사용자가 움직임을 보고 한다.
- 헤드리스 검수는 설치된 크롬을 직접 띄운다. 예: `project/m007/head_turn_v8/scripts/qa_capture.mjs`, `qa_playback.mjs` (playwright: `~/.npm/_npx/9833c18b2d85bc59/node_modules/playwright`, 크롬: `~/Library/Caches/ms-playwright/chromium-1228/...`). **Playwright MCP는 사용자의 실제 크롬 탭을 조작하므로 검수에 쓰지 않는다.**
- 템플릿 플레이어의 `window.__headturn.set(각도, {nod, tilt, blink})`로 특정 자세를 고정할 수 있다.

## 7 한계

- 정면 한 장 기준 ±30° 정도가 자연스러운 범위다. 완전한 옆모습·뒷모습은 별도 원화로 교체해야 한다.
- 반대쪽 귀처럼 원화에 아예 없는 부위는 나타나지 않는다(옆모습에서 같은 방식으로 가져올 수는 있다).
- 입은 닫힌 상태다. 말하기·립싱크는 아직 이 파이프라인에 없다.
- 레이어는 래스터 텍스처(원화 2배)다. Live2D와 같은 방식이며 벡터는 아니다.

## 8 채색 원화·몸 움직임으로 확장한 예 (M010)

`project/m010/`에서 이 방식을 채색 원화 4인, 몸·손·망토까지 넓혀 10초 영상을 만들었다. 채색용 분리는 `project/m010/scripts/cut_color.py`, 머리+몸 런타임은 `project/m010/web/actor.js`.

- 채색 원화는 레이어 밑을 흰색이 아니라 **주변 색으로** 메운다: 앞머리 밑 이마=피부, 얼굴 뒤=뒤통수 전체를 머리카락 색, 턱 밑=목 피부(크림색 옷깃이 피부로 분류되므로 목 폭+채도로 제한), 손 밑=옷.
- 눈을 감을 때 드러나는 자리는 주변 그늘이 아니라 **바로 아래 볼 피부의 고른 색**으로. 그늘·속눈썹 색이 섞이면 회색 띠가 생긴다.
- 숙임·젖힘(pitch)은 얼굴 장이 아니라 **두개골(머리카락) 장 + 코·입 돌출**로 움직인다. 얼굴 장으로 하면 이마 위쪽과 머리선이 다르게 움직여 머리선이 들뜬다.
- 뒷머리 레이어는 앞머리 자리까지 포함해 둔다(같은 변형장이라 겹쳐도 같은 그림). 앞·뒷머리 경계 틈이 사라진다.
- 몸은 같은 규칙: 몸 깊이장으로 머리보다 작게 돌기, 어깨·가슴 가중치 숨쉬기, 망토 가중치 용수철 지연, 손은 소매→손끝 가중치로 부드럽게 회전. 손 레이어는 상자 안 피부색 픽셀만(망토 가장자리가 손과 같이 돌지 않게).
- **얼굴형 보존(2026-10-25 사용자 지적: 턱이 뾰족해져 얼굴이 바뀜):** 얼굴 깊이장은 `base`(통째 이동) + 얕은 돔으로 한다. 가로 눌림 = 돔 기울기(≈ rz·π/2 / rx) × sin(최대 각도)을 **10% 이하**로 유지하고, 턱·입 돌출(bump)은 넣지 않는다. 시차는 머리카락 장과의 차이로 충분하다.
- 결과는 MP4 대신 웹 플레이어 + 보정 패널(움직임 배율·깊이장 슬라이더, rig.json 저장)로 넘긴다(사용자 선호).
